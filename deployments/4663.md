## Address constraints

The deployed Aggregator address is:

```text
0xd11758Ec960e365Df35E3790b172B25c708A6888
```

It satisfies both address-level routing/permission constraints used during mining:

```text
first-byte ID = 0xD1
hook flags    = 0x2888 = 10376 decimal
```

`0xD1` is the ID used by this deployment and remains a **proposed upstream Aggregator Hook ID**. As checked on **2026-08-21**, it is not listed in the public upstream ID table. If the eventual upstream integration uses a different ID, a new Aggregator address must be mined and deployed.

## Verification scope and provenance

`VerifyDeepStateDeployment.s.sol` verifies the current on-chain code presence, contract bindings, first-byte ID and low-14-bit hook flags. It does **not** independently attest the historical creation transaction, CREATE2 deployer, transaction hash or deployment block.

The CREATE2 deployer above is the one configured by the repository's mining/deployment tooling. The deployment transaction hashes are recorded above. Block numbers are not asserted here because they were not independently extracted during this documentation pass; add them later from the retained Foundry `broadcast/` artifacts or indexed explorer metadata if desired.
